    REFERENCE · METADATA CHEATSHEET

    Agent 集成：metadata 设置哪些内容

    一次性查询表 · 告诉你 session_id / user_id / tags / metadata 各放什么、怎么设
    本表目标
    集成 Langfuse 到 agent 时，4 类附加信息（session_id / user_id / tags / metadata）该放什么、怎么设、避坑清单。

    1. 先理清一个概念：metadata 不是全部

    Langfuse 一条 trace 上能附加 5 类信息，不是 metadata 一锅端：

    类型设置位置UI 上长什么样
    session_id顶级字段trace 顶部一栏，可聚合整个会话
    user_id顶级字段trace 顶部一栏，可按用户聚合
    tags顶级字段（数组）trace 顶部 chip，可过滤
    trace_name顶级字段左侧 Tracing 列表里显示
    metadata任意键值对 dict"Metadata" 折叠面板

    所以"metadata 设置哪些内容"其实要回答 5 个子问题。下面逐个回答。

    2. session_id — 多轮对话的关联纽带

    什么时候设

    凡是涉及"用户连续问几轮"的场景都要设：

    场景session_id 策略
    客服对话同一会话内所有 trace 共用一个 session_id
    单次 ReAct Agent一次用户提问 = 一个 session_id（即使内部多次 tool call）
    批处理任务每个 batch = 一个 session_id（聚合这批的 stats）

    值怎么生成

    import uuid
session_id = f"sess-{uuid.uuid4().hex[:12]}"
    ⚠️ 坑：不要用明文邮箱 / 手机号当 session_id（涉及 GDPR / 隐私合规）。前端传上来时先哈希。

    3. user_id — 强烈推荐

    即使不知道真实身份，也可以用 IP + UA 哈希：

    import hashlib
user_id = hashlib.sha256(f"{ip}-{ua}".encode()).hexdigest()[:16]

    UI 上 user_id 字段打开后能直接看：这个用户最近 50 次 trace、平均多少 token、成功率多少。在做质量回溯时巨有用。

    4. trace_name — 让 trace 在 UI 里好认

    默认会显示类名（LangGraph / ChatOpenAI）这种没意义的东西。一定要覆盖：

    "langfuse_trace_name": "research-agent-v2"

    命名建议：{业务线}-{agent 名}-{版本} 或 {用户动作}-{特征}。例如 checkout-recommend-v3、user-question-first-turn。

    5. tags — 最便宜的维度切分

    用途示例值
    环境prod / staging / dev
    业务线checkout / recommendation / support
    实验ab-A / ab-B / canary
    状态error / timeout / retry
    特征streaming / multimodal / function-call

    tag 的核心价值是过滤。在 UI 顶部搜索栏打 tag:prod 就能只看生产环境的 trace。

    ⚠️ 坑：tag 是字符串数组，不要堆太多（建议 ≤ 5 个）。高基数 tag（如 uuid-per-request）失去过滤意义。

    6. metadata dict 放什么（核心问题）

    必设（一个不能少）

    Key类型示例为什么
    agent_namestr"research-agent"区分多个 agent 定义（同一服务可能跑多个 agent）
    agent_versionstr"2.1.0" 或 git sha跨版本对比、灰度验证、回归测试
    environmentstr"prod"等同 tag，但 metadata 更结构化、易聚合

    推荐设

    Key类型示例何时用
    app_versionstr"1.4.2"应用包版本（区别于 agent 版本）
    deployment_idstr"pod-7f3a"多副本时定位是哪台机器出了问题
    request_idstr"req-2026-09-16-xxx"与上游追踪系统（OpenTelemetry / Sentry）对齐
    input_sourcestr"web" / "api" / "cron"区分请求来源
    feature_flagsdict{"new_prompt": true}关联 A/B 测试 / 灰度开关
    model_configdict{"temperature": 0, "max_tokens": 1024}同一模型不同参数下的对比

    选设（看场景）

    场景推荐加的 metadata
    多 agent 协同parent_agent_id、delegation_reason
    RAG 应用retriever、retrieved_doc_count、retrieval_score_avg
    业务追踪product_id、order_id、customer_tier
    工具调用tool_version、tool_retry_count
    多语言user_locale、input_language

    7. 设置方式（3 种）

    方式 A：LangChain metadata 入口（最常用）

    直接放在 invoke 的 config 里：

    from langfuse.langchain import CallbackHandler

handler = CallbackHandler()
config = {
    "callbacks": [handler],
    "metadata": {
        # langfuse 约定 key（带前缀）— 自动识别
        "langfuse_session_id": "sess-abc123",
        "langfuse_user_id": "u-9f3a",
        "langfuse_tags": ["prod", "agent"],
        "langfuse_trace_name": "research-agent-v2",

        # 普通 metadata — 原样存
        "agent_name": "research-agent",
        "agent_version": "2.1.0",
        "environment": "prod",
        "deployment_id": "pod-7f3a",
        "feature_flags": {"new_prompt": True},
    },
}
result = agent.invoke(input, config=config)
    ⚠️ 坑：四个 langfuse 约定 key 必须带 langfuse_ 前缀。裸 session_id 不会触发任何特殊处理——它会被当成普通 metadata。

    方式 B：propagate_attributes（上下文管理器）

    适合中间件或外层装饰器，自动传播到所有子 observation：

    from langfuse import propagate_attributes

with propagate_attributes(
    user_id="u-9f3a",
    session_id="sess-abc123",
    tags=["prod"],
    metadata={"agent_version": "2.1.0"},
):
    result = agent.invoke(input, config={"callbacks": [handler]})

    这个写法的好处：不需要把 metadata 字典塞到 config 里，适合外层框架代码。缺点是侵入性更强（用了 with 块）。

    方式 C：在 custom Span 里手动 update

    适合嵌套业务逻辑，给特定一段加专属 metadata：

    from langfuse import get_client

lf = get_client()
with lf.start_as_current_observation(
    as_type="span", name="preprocess"
) as span:
    span.update(metadata={"step": "user_lookup", "matched": True})
    user = lookup_user(user_id)

    8. UI 上怎么查

    想看什么怎么查
    某条 trace 的 metadata点开 trace → 顶部 "Metadata" 折叠面板
    按 session_id 看所有 trace左侧 Sessions 标签页 → 输入 session_id
    按 user_id 看统计左侧 Users 标签页
    按 tag 过滤顶部搜索栏 tag:prod
    按 metadata 字段过滤顶部搜索栏 metadata.environment=prod
    多条件tag:prod metadata.environment=prod session_id:sess-abc

    9. ⚠️ 不要放什么

    不要放为什么替代
    PII（明文邮箱 / 手机号 / 身份证）GDPR / 隐私合规哈希后当 user_id
    大段 prompt / response 原文已经有 input / output 字段，重复浪费存储不放
    高基数 ID（每条都不同的 UUID）失去聚合意义放但用低基数 tag 聚合
    密钥 / Token / 密码安全隐患（哪怕自托管也有日志泄漏风险）永不放
    业务核心数据（订单详情、银行卡）合规问题只放脱敏后的引用 ID
    巨大嵌套对象（>10 KB）UI 渲染慢、查询慢用 Langfuse Media API 存

    10. 完整示例：Agent 一次性带上全部

    import os, uuid, hashlib
from langfuse.langchain import CallbackHandler

def build_agent_config(request) -> dict:
    user_id = hashlib.sha256(
        f"{request.ip}-{request.ua}".encode()
    ).hexdigest()[:16]

    return {
        "callbacks": [CallbackHandler()],
        "metadata": {
            # 4 个 langfuse 约定 key
            "langfuse_session_id": request.session_id or f"sess-{uuid.uuid4().hex[:12]}",
            "langfuse_user_id": user_id,
            "langfuse_tags": [os.getenv("ENV", "dev"), "agent", "v2"],
            "langfuse_trace_name": f"checkout-recommend-v2-{request.turn}",

            # 业务 metadata
            "agent_name": "checkout-recommender",
            "agent_version": "2.1.0",
            "environment": os.getenv("ENV", "dev"),
            "deployment_id": os.getenv("POD_NAME", "local"),
            "app_version": "1.4.2",
            "input_source": request.source,           # "web" / "api"
            "feature_flags": {"new_ranker": True},
            "model_config": {"temperature": 0.3, "max_tokens": 512},
            "customer_tier": request.user_tier,
        },
    }

# 用
result = agent.invoke(input, config=build_agent_config(request))

    11. 速查卡（一页打印版）

    ┌─ 4 个 langfuse_* 顶级字段 ─────────────────────────┐
│ langfuse_session_id    → 多轮聚合                   │
│ langfuse_user_id       → 用户级聚合                 │
│ langfuse_tags          → 过滤 (env/feature/experiment) │
│ langfuse_trace_name    → 覆盖默认 trace 名          │
└────────────────────────────────────────────────────┘

┌─ metadata 必设 3 项 ────────────────────────────────┐
│ agent_name      "research-agent"                    │
│ agent_version   "2.1.0" 或 git sha                  │
│ environment     "prod" / "staging" / "dev"          │
└────────────────────────────────────────────────────┘

┌─ metadata 推荐 6 项 ────────────────────────────────┐
│ app_version, deployment_id, request_id,             │
│ input_source, feature_flags, model_config           │
└────────────────────────────────────────────────────┘

⚠️ 不要放：PII、大段原文、高基数 ID、密钥
