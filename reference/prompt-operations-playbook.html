    Prompt 运维 SOP

    6 个核心场景 + 5 步部署 + 缓存策略 + 回滚机制。直接抄就能用。
    本页目标
    不解释原理，只讲步骤：日常改 prompt、A/B、回滚、废弃时该走哪套流程。每一步都配可直接复制的命令或 UI 操作。

    1. 6 个核心场景

    场景 A：新建一个 prompt（首次）

    UI 路径：Prompts → + New Prompt → 填 5 栏 → Save

    栏填什么例子
    Name唯一名（小写连字符）checkout-recommender
    TypeText 或 ChatText（单字符串）
    Prompt模板字符串，用 {{var}}Recommend products for {{user_segment}}...
    Labels默认勾 production["production"]
    Commit msg这次发布做了什么initial version, A/B test ready

    SDK 等价：

    lf.create_prompt(
    name="checkout-recommender",
    type="text",
    prompt="Recommend products for {{user_segment}}: ",
    labels=["production"],
    config={"model": "gpt-4o", "temperature": 0.5},
    commit_message="initial version",
)
    ⚠️ labels=["production"] 会让旧 production 版本失去这个 label——这是默认行为，新版本生效、旧版本下线。

    场景 B：改一个 prompt（线上已有，要换）

    最稳的做法（4 步）：

    1. UI: Prompts → checkout-recommender → Edit → 改 prompt 文字 → Save（自动创建 v2）→ Labels 不勾 production（保持 v1 在线）
    2. UI: 给 v2 加 staging label（可选，看你要不要预发）
    3. 改代码：在配置里切到 staging 验证 prompt = lf.get_prompt("checkout-recommender", label="staging")
    4. 验证 OK 后：UI 把 v2 的 labels 加上 production。v1 的 production 会自动被夺走。5 秒 + 缓存 TTL 后所有线上请求都用 v2
    ⚠️ 不要直接 create_prompt 时打 production。否则没法"先看一下效果再决定"——线上立刻全切，改坏了只能用 UI 回滚。

    场景 C：对比两个版本

    UI 路径：Prompts → checkout-recommender → 选 v1 / v2 → Diff 标签

    SDK 跑对比：

    v1 = lf.get_prompt("checkout-recommender", version=1)
v2 = lf.get_prompt("checkout-recommender", version=2)

# 跑同一个 input，看两个版本的输出
print("v1:", llm.invoke([{"role": "user", "content": v1.compile(user_segment="new_visitor")}]))
print("v2:", llm.invoke([{"role": "user", "content": v2.compile(user_segment="new_visitor")}]))

    场景 D：A/B 测试

    核心模式：同一 prompt 名 + 多个版本 + 不同 label，运行时按比例分流。

    import hashlib
from langfuse import get_client

lf = get_client()
A = lf.get_prompt("checkout-recommender", label="production")
B = lf.get_prompt("checkout-recommender", label="experiment-b")

def get_prompt_ab(user_id: str):
    bucket = int(hashlib.md5(user_id.encode()).hexdigest(), 16) % 100
    return A if bucket < 50 else B

# 调用时
p = get_prompt_ab(user_id="u-9f3a")
compiled = p.compile(user_segment="new_visitor")
resp = llm.invoke(...)

# trace 上标记 bucket，方便后续分析
lf.update_current_generation(
    prompt=p,
    metadata={"ab_bucket": "A" if p.version == A.version else "B"},
)

    场景 E：回滚

    最快的回滚（30 秒）：

    1. UI: Prompts → checkout-recommender
    2. 找到上一个稳定版本（看 commit_message 找最近的 known-good）
    3. 把 production label 切到那个版本
    4. 5 秒 + 缓存 TTL 后所有线上请求回到旧版
    关键：commit_message 要写人话。
    • ❌ update prompt
    • ✅ v3: add safety disclaimer, before that A/B test showed +12% conversion
    回滚时靠这个知道回到哪版。

    场景 F：废弃 prompt（清理）

    UI: Prompts → 选 prompt → Archive

    Archive 不删数据，只是不在 UI 默认列表显示。已经发出的 trace 仍然引用那个 prompt 版本——这是好事，可以回看历史。

    2. 部署 5 步（官方原文）

    1. Create and test   创建新版本（自动获 latest）
2. Validate — 在 dev / playground 验证
3. Deploy — UI 把 production 切到新版本
4. Monitor — 下次 fetch 生效（含缓存延迟）
5. Rollback if needed — 切回上一版

    代码侧不用改任何东西——因为代码引用 label 而不是 version。

    3. 真实时间线（含缓存延迟）

    T+0s  UI: create new version v3（labels=["latest"]）
       v2 仍带 production，v3 只带 latest
T+5s   测试用 staging 环境拉 v3 验证
T+30s  UI: 给 v3 加上 production label
       v2 失去 production
       v3 现在 labels=["production", "latest"]
T+30s  ← 这一刻线上还没切换！（缓存未过期）
T+90s  默认 TTL（60s）过后，所有新请求拿到 v3
T+90s+ 监控指标开始反映 v3
T+∞   如果 v3 表现差：UI 把 production 切回 v2 → 60s 后生效

    4. Caching 配置矩阵

    场景配置
    默认（推荐生产）get_prompt(name)（隐式 60s）
    长 TTL（高可用优先）get_prompt(name, cache_ttl_seconds=300)
    立即生效（紧急修复）get_prompt(name, cache_ttl_seconds=0)
    Langfuse 挂了也能跑get_prompt(name, fallback="...")
    完全离线可用CLI: langfuse prompt fetch 拉成本地文件
    ⚠️ fallback 不建立 link——这是设计如此，不是 bug。fallback 等于没真连上 Langfuse，假装 link 会误导调试。

    5. 团队协作的角色分工

    角色改 prompt 路径不能做的事
    PM / 业务方UI 直接改 + 加 commit_message不能直接动 production label（要 engineer 审批）
    算法 / engineerUI 改 → 自加 staging → 跑 eval → 切 production—
    新人只读，看 UI 历史不能动任何 prompt

    Protected Labels（Enterprise）可以把 production 设为受保护——viewer / member 不能改，只有 admin / owner 能动。

    6. 跟代码同步的双轨问题

    场景后果修法
    prompt 加了新变量 {{foo}}，代码没传UI 里 prompt 是 {{foo}} 原样保留unit test 校验 compile() 后没有 {{ 残留
    代码加了新参数 foo="bar"，prompt 没用到多余参数不影响（无害）给 prompt 加注释说明哪些变量是必填
    旧代码引用了已删除的 prompt 名运行时 PromptNotFoundError灰度发布前跑 canary
