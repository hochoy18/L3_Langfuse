    Prompt 踩坑速查

    8 个常见坑 + 调试 SOP + 5 个反直觉但正确的认知。遇到问题先查这张表。
    本页目标
    把所有新手容易踩的坑集中放一页。每一个坑都配"现象 → 原因 → 修法"三段式。写代码 / on-call 的时候查得到。

    1. 8 个最常见的坑

    坑 1：传字符串而不是 PromptClient 对象

    详情
    现象UI 上 trace 的 input 字段有 prompt 文字，但没有 prompt 徽章
    原因update_current_generation(prompt="字符串")，Langfuse 拿不到 .name / .version
    修法改 prompt=p（PromptClient 对象）
     
    # ❌ 错
lf.update_current_generation(prompt=compiled_str)

# ✅ 对
lf.update_current_generation(prompt=p)

    坑 2：参数名写错（usage 而非 usage_details）

    详情
    现象TypeError: Langfuse.update_current_generation() got an unexpected keyword argument 'usage'
    原因SDK v3 参数名跟 OTEL 协议对齐，叫 usage_details
    修法改 usage_details=
     
    # ❌ 错
lf.update_current_generation(usage={"input": ..., "output": ...})

# ✅ 对
lf.update_current_generation(usage_details={
    "input_tokens": ...,
    "output_tokens": ...,
    "total_tokens": ...,
})

    坑 3：误解默认行为（以为是取最新版本）

    详情
    现象以为 get_prompt(name) 拿版本号最大的那个
    原因实际默认拉取带 production label 的版本
    修法记住这条规则。如果要拉最新版，显式 label="latest"
     
    p = lf.get_prompt(name)                # 默认 production
p = lf.get_prompt(name, label="latest")  # 显式 latest

    坑 4：代码引用 label="latest" 当 production 用

    详情
    现象每次发新版本都自动生效，等于裸奔发版
    原因代码侧写 get_prompt(name, label="latest")
    修法永远引用 production（不传 label 参数）
    ⚠️ latest 是给你看新版本用的，不是上线用的。

    坑 5：create_prompt 时直接打 production

    详情
    现象新版没验证就上线，改坏了只能 UI 回滚
    原因create_prompt(labels=["production"]) 会让旧 production 失去 label
    修法先 labels=[]，UI 验证后再切 production

    坑 6：@observe() 默认 span 包 LLM 调用

    详情
    现象UI 上节点是 span（⏱️），没有 model / usage / prompt 渲染
    原因没指定 as_type="generation"
    修法改 @observe(as_type="generation", name="...")

    坑 7：compile 变量名拼错

    详情
    现象占位符 {{criticlevel}} 原样保留，输出 "As an {{criticlevel}} movie critic..."
    原因compile() 参数名拼错（critical_level vs criticlevel）
    修法加 unit test 校验 compile() 后没有 {{ 残留
     
    def test_prompt_compile():
    compiled = p.compile(criticlevel="harsh", movie="Dune 2")
    assert "{{" not in compiled, f"未替换的占位符: {compiled}"

    坑 8：改 prompt 后立即查 trace 没生效

    详情
    现象UI 切 label 后，前几条 trace 还在用旧版
    原因客户端缓存未过期（默认 60s）
    修法等 TTL，或设 cache_ttl_seconds=0 立即生效

    2. 调试 SOP

    遇到问题，按下面顺序查：

    问题类型第一步第二步
    UI 看不到 trace检查 flush() 是否调用检查 API key 是否正确
    trace 没 prompt 徽章确认 update_current_generation(prompt=...) 传的是对象确认 @observe(as_type="generation")
    变量没替换检查占位符和传参 key 是否完全一致加 unit test
    Token 数不对检查 usage_details 参数名（不是 usage）检查 resp.usage_metadata 是否非空
    改了 prompt 线上没变等缓存过期（默认 60s）检查 cache_ttl_seconds 配置
    PromptNotFoundError检查 UI 上 Labels 栏有没有 production检查 prompt 名拼写
    fallback 路径没 link这是设计如此查 Langfuse web 日志

    3. 5 个反直觉但正确的认知

    #反直觉的事实际情况
    1"默认取最新版本"默认取 production label 的版本
    2"一个 label 只能挂一个版本"除 production 和 latest 外，其他 label 可以多版本同时挂
    3"audit_logs 记所有改动"当前只审计 create，label 切换不审计
    4"UI 切 label 立刻生效"有缓存延迟（默认 60s）
    5"fallback 会建立 link"不会（设计如此）
