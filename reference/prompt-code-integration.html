    Prompt 代码接入

    4 个核心 SDK 调用 + @observe 装饰器 + 6 种 link 模式 + 绑定本质。
    本页目标
    一次性查清楚"在 Python 代码里怎么用 Langfuse Prompt Management"——所有 SDK 调用、所有装饰器选项、所有把 prompt 链接到 trace 的姿势。

    1. 4 个核心 SDK 调用

    from langfuse import get_client
lf = get_client()

# 1. 创建（带 label + config + commit_message）
lf.create_prompt(
    name="movie-critic",
    type="text",
    prompt="As a {{criticlevel}} movie critic, give a one-line take on {{movie}}.",
    labels=["production"],
    config={"temperature": 0.7, "model": "MiniMax-M3"},
    commit_message="initial version",
)

# 2. 获取（默认取 production）
p = lf.get_prompt("movie-critic")              # 取 production
p = lf.get_prompt("movie-critic", label="staging")
p = lf.get_prompt("movie-critic", version=3)   # 不推荐

# 3. 编译（替换 {{var}}）
compiled = p.compile(criticlevel="harsh", movie="Dune 2")

# 4. 修改 label（生产/回滚/A/B 用）
lf.update_prompt(
    name="movie-critic",
    version=2,
    new_labels=["production"],   # ⚠️ 全量替换，漏写 = 丢 label
)

    属性类型含义
    p.namestr"movie-critic"
    p.versionint1

    p.configdict{"temperature": 0.7, "model": "..."}

    3. @observe(as_type="generation", name="...") 详解

    参数作用不传会怎样
    as_type="generation"标记为 LLM 调用节点（多 model/usage/prompt 专属字段）用默认 span → UI 没这些字段的渲染
    name="ask-critic"UI 显示名默认用 Python 函数名（往往不清晰）
    metadata=...一次性 metadata dict—
    tags=...一次性 tags list—
    capture_input=False是否自动捕获函数 args默认 False（手动控制更好）
    user_id / session_id / trace_name透传到外层 trace—

    @observe 自动干的事：

    1. 函数进入 → 创建 observation + 绑当前 trace_id
    2. 函数正常返回 → 标记 level=DEFAULT、设置 end_time、异步上报
    3. 函数抛异常 → 标记 level=ERROR、statusMessage 填异常文本
    4. 中间所有 update_current_* 自动归属到这条 observation

    4. 6 种 link 方式（prompt ↔ trace）

    集成link 怎么传
    Langfuse SDK 装饰器update_current_generation(prompt=p)
    Langfuse SDK context managerstart_as_current_observation(..., prompt=p)
    OpenAI SDK (Python)openai.chat.completions.create(..., langfuse_prompt=p)
    OpenAI SDK (JS/TS)observeOpenAI(client, { langfusePrompt })
    LangChainPromptTemplate(..., metadata={"langfuse_prompt": p})
    Vercel / LiteLLM 等三方with propagate_attributes(prompt=p):

    所有方式的核心都是同一个——传 PromptClient 对象，不是字符串。让 Langfuse 拿到 .name / .version 建立版本链接。

    5. 3 种"传 prompt"的位置含义

    位置何时 link 生效适用
    update_current_generationLLM 调用之后默认场景
    start_observation(prompt=)observation 创建瞬间一次性 context
    metadata.langfuse_prompt框架读 metadata 时（callback）框架集成

    6. 绑定的本质

    绑定 = 写 3 个字段到 generation 节点：

    promptName    = "movie-critic"   ← 来自 PromptClient.name
promptVersion = 1                ← 来自 PromptClient.version
promptId      = "fc9cdbfb-..."   ← 来自 PromptClient.id

    写进去 = 绑定建立；不写 = 绑定没建。

    7. 完整 demo 骨架

    from langfuse import get_client, observe
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="...", api_key=..., base_url=...)
lf = get_client()

@observe(as_type="generation", name="ask-critic")
def ask(criticlevel: str, movie: str) -> str:
    # 1. 拿 prompt
    p = lf.get_prompt("movie-critic")
    compiled = p.compile(criticlevel=criticlevel, movie=movie)

    # 2. 第一次 update：建立 link + 记 model
    lf.update_current_generation(
        prompt=p,                                # ← 必须传对象，不是字符串
        model=p.config.get("model", "..."),
    )

    # 3. 调 LLM
    resp = llm.invoke([
        {"role": "system", "content": compiled},
        {"role": "user", "content": movie},
    ])

    # 4. 第二次 update：记 token
    usage_md = resp.usage_metadata or {}
    lf.update_current_generation(
        usage_details={                          # ← 参数名是 usage_details 不是 usage
            "input_tokens": usage_md.get("input_tokens", 0),
            "output_tokens": usage_md.get("output_tokens", 0),
            "total_tokens": usage_md.get("total_tokens", 0),
        },
    )
    return resp.content
