    REFERENCE · PROMPT DATA MODEL

    Prompt 数据模型

    Version / Label / 不可变性 / 默认行为。Lesson 0004 的配套深度参考。
    本页目标
    把 Langfuse Prompt Management 的核心抽象讲透：Prompt 对象由哪几部分组成、Version 和 Label 各自的角色、默认行为到底是什么、哪些字段可变哪些不可变。

    1. Prompt 对象 = 5 个组成部分

    部分例子说明
    name"movie-critic"跨版本共用的逻辑键，全局唯一
    version1、2、3...name 内单调递增整数
    prompt（内容）"As a {{criticlevel}}..."text = 字符串 / chat = messages 数组
    config{"model": "gpt-4o", "temperature": 0.7}模型参数，跟 prompt 绑死
    labels["production"]部署指针，唯一可变字段

    2. Version vs Label（核心二元论）

    VersionLabel
    谁维护Langfuse 自动递增你手动管理
    可变性不可变（内容创建后永远不动）可变（随时换）
    数量每次改动 +1一个 prompt 上可以有多个 label
    作用历史快照部署指针
    代码引用❌不用✅get_prompt(name) 默认取 production

    铁律：改 prompt = 发新版本；切换部署 = 改 label。代码只引用 label。

    3. 不可变 vs 可变字段（实测表）

    字段创建后能改吗怎么改
    name❌不可改
    version❌不可改
    type（text/chat）❌要换就建新 prompt 名
    prompt 内容❌发新版
    config❌发新版
    commit_message❌发新版
    created_at❌—
    labels✅ 可变update_prompt() 或 UI 编辑
    tags✅ 可变同上
    updated_at自动任何字段被改时更新

    4. Label 机制

    4.1 4 类 label

    Label谁维护同时可挂在几个版本含义
    production手动1 个线上跑这版
    latestLangfuse 自动1 个（强约束）总是最新版本
    staging手动可以多预发环境
    任意自定义手动可以多A/B / 灰度 / 租户

    4.2 默认行为（最常被误解的点）

    get_prompt(name)            # → 拉取带 "production" label 的版本
get_prompt(name, label="latest")  # → 拉取最新版本
get_prompt(name, version=3) # → 拉取指定版本号
    ⚠️ 纠错：get_prompt(name) 不传任何参数时，不是拉取版本号最大的那个，而是拉取带 production label 的版本。这是设计上的安全机制——强制要求显式部署。

    4.3 latest 的自动维护规则

    创建 v2 时，Langfuse 在一个事务里同时干三件事：

    1. 插入 v2 行
2. v2.labels += ["latest"]      ← 自动加
3. v1.labels -= ["latest"]      ← 之前有就摘掉

    所以 v1 的 updated_at 会等于 v2 的 created_at——这是"latest 自动转移"的物理痕迹。

    ⚠️ latest 是 SDK 硬保护（实测发现，文档没明说）： 
    # ❌ 试图手动改 latest → 服务端 400 拒绝
lf.update_prompt(version=2, new_labels=["latest"])
# Error: "Label 'latest' is always assigned to the latest prompt version"
    任何试图通过 update_prompt 改 latest label 的请求都会被服务端拦截。

    4.4 production 的单一性

    问题答案
    只有一个版本带 production 吗？✅ 是
    只有一个版本带 staging 吗？❌ 不一定（可以多）
    production 和 staging 能同时挂在不同版本吗？✅ 可以

    常见的多 label 状态：

    v1: labels = ['production']            ← 线上
v2: labels = ['staging', 'latest']      ← 预发测试最新

    4.5 update_prompt 的全量替换语义

    lf.update_prompt(name="movie-critic", version=1, new_labels=["production", "archived"])
# v1.labels 现在 = ["production", "archived"]
# 是【新状态全量替换】，不是【增量追加】

lf.update_prompt(name="movie-critic", version=1, new_labels=["archived"])
# ⚠️ v1.labels 现在 = ["archived"]（production 被摘走了！）

    6. Caching 副作用

    Langfuse 客户端缓存 prompt（默认 60s），改 prompt 后前几条 trace 仍可能用旧版。

    操作行为
    默认第一次拉后缓存 60s
    关闭缓存get_prompt(name, cache_ttl_seconds=0)
    fallback 参数get_prompt(name, fallback="...") 拉取失败时返回本地字符串
    is_fallback=True不会建立 prompt link（设计如此）
