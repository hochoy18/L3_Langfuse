    LESSON 0004 · PROMPT MANAGEMENT

    把 Prompt 搬出代码，用 Langfuse 做版本管理

    预计 30 分钟 · 难度 ★★★☆☆ · 产出：prompt 在 UI 里改一行代码不用动；trace 上自动出现 prompt 徽章
    本节目标
    把硬编码在 Python 字符串里的 system prompt 搬到 Langfuse 的 Prompt Management。改 prompt 不再需要发版；UI 上能看到哪条 trace 用了哪个版本；回滚一行 label。

    1. 为什么 prompt 要搬出代码

    上一节 trace 树有了，但 prompt 还是写死在 system = "你是一个..." 里——这意味着每次调 prompt 都要发版一次代码。先看两者差异：

    维度硬编码在代码里搬到 Langfuse
    改一个措辞改代码 → 走 PR → CI → 部署UI 改 → 下一个请求就用上
    对比新旧 prompt手动 git diffUI 里逐版本 diff，自带评分对比
    回滚git revert + 重部署把 production label 切回旧版本
    trace 关联只能从 input 里反推用的是哪版UI 上每条 trace 带 prompt 徽章，链回具体版本
    非工程师协作提 PR 给工程师改PM 自己登录 UI 改
    直觉：Prompt Management 解决的是 "prompt 是产品的一部分，而不只是代码的一部分"。它本来就不是字符串常量——它是有版本、需要对比、能回滚的资产。

    2. 三个核心概念

    概念是什么类比
    Prompt一个具名的 prompt 对象（如 movie-critic）Git 仓库
    VersionPrompt 的一次发布。整数，自增Git commit
    Label贴在某个 Version 上的可读指针（production / staging / latest）Git branch / tag

    关键关系：

    Prompt "movie-critic"
 ├─ v1  labels=["production", "latest"]   ← 线上跑这版
 ├─ v2  labels=["latest"]                 ← 刚编辑，没上线
 └─ v3  labels=["staging"]                ← 准备 A/B

    SDK 默认 get_prompt(name) 拿的是带 production label 的版本。如果没人打 production，会报错（详见 §7）。

    ⚠️ 坑：latest 是 Langfuse 自动维护的 label，永远指向最新版本。生产环境 永远不要 fetch by latest——那等于裸奔发版，没有 label 这层开关保护。

    3. 第一步：创建你的第一个 prompt

    两种方式——先用 UI 看到形状，再用 SDK 写代码。

    方式 A：UI 创建（最快）

    1. 浏览器 localhost:3000
    2. 左侧 Prompts → + New Prompt
    3. 填三栏： 
      Name:       movie-critic
Type:       Text
Prompt:     As a {{criticlevel}} movie critic, do you like {{movie}}?
Labels:     production
Commit msg: initial version
    4. Save

    方式 B：SDK 创建（可放进 CI / 一次性脚本）

    # seed_prompt.py  —— 一次性脚本，跑完即可删
from langfuse import get_client

lf = get_client()
lf.create_prompt(
    name="movie-critic",
    type="text",
    prompt="As a {{criticlevel}} movie critic, do you like {{movie}}?",
    labels=["production"],
    config={"temperature": 0.7},          # 任何额外参数，可放模型/温度
    commit_message="initial version",
)
print("created, version =", lf.get_prompt("movie-critic").version)

    create_prompt 的行为：同名 prompt 再次调用会创建新版本（不是覆盖）。Labels 是贴在那个新版本上的，旧的带 production 标签的版本会失去这个 label（详见 §4）。

    ⚠️ 坑：UI 和 SDK 都能创建 prompt，但修改已经发布的版本不行。一旦某个版本被 trace 引用，它就是历史——只能发新版。这也意味着 create_prompt 默认每次都新建版本，不会就地改。

    4. 第二步：在代码里拿 prompt

    4.1 默认拿法（拿 production）

    from langfuse import get_client

lf = get_client()
prompt = lf.get_prompt("movie-critic")        # 默认 label="production"
print(prompt.name, prompt.version, prompt.labels)
# movie-critic 1 ['production', 'latest']

print(prompt.prompt)
# "As a {{criticlevel}} movie critic, do you like {{movie}}?"

    4.2 三种获取维度

    调用拿什么何时用
    get_prompt(name)带 production label 的版本线上代码（默认安全）
    get_prompt(name, label="staging")带 staging label 的版本预发环境 / 灰度对比
    get_prompt(name, label="latest")Langfuse 自动维护的最新版本预发看新效果（不要上 prod）
    get_prompt(name, version=3)指定版本号回归测试 / 复现某条历史 trace

    4.3 返回对象的字段

    p = lf.get_prompt("movie-critic")

p.name            # str: "movie-critic"
p.version         # int: 1
p.labels          # list[str]: ["production", "latest"]
p.config          # dict: {"temperature": 0.7}
p.tags            # list[str]: []
p.commit_message  # str | None: "initial version"
p.is_fallback     # bool: False（True = 本地 fallback 顶上来的，见 §7）
p.prompt          # str: "As a {{criticlevel}} movie critic, do you like {{movie}}?"
    说明：p.config 是创建时传的自由 dict，常用来塞模型名、温度这种"和这个 prompt 绑死的参数"——代码里就不用到处写散落的 temperature=... 了。

    5. 第三步：compile 替换变量

    {{criticlevel}} 这种 {{var}} 占位符是 Langfuse 自家语法（不是 Python f-string，也不是 Jinja）。替换用 .compile(**kwargs)：

    p = lf.get_prompt("movie-critic")
msg = p.compile(criticlevel="expert", movie="Dune 2")
print(msg)
# "As an expert movie critic, do you like Dune 2?"
    ⚠️ 坑：变量名必须严格匹配——{{criticlevel}} 传 critical_level 不会报错，但占位符原样保留，会拼出 "As an {{criticlevel}} movie critic..."。这种 bug 在 prompt 长的时候很难看出来。
    ⚠️ 坑（更隐蔽）：如果变量值里碰巧含 {{xxx}}，.compile() 不会二次转义（不是 Jinja）。所以传入的内容一定要你自己 sanitize。

    6. 第四步：把 prompt 接到 LLM 调用上（杀手功能）

    拿到 prompt + compile 之后，最直接的方式就是拼到 messages 里调 LLM。但 Langfuse 真正的杀手锏是在 trace 上自动显示 prompt 徽章——告诉你这条 trace 用了哪个版本。这个关联需要显式声明一次：

    from langfuse import get_client, observe
from langchain_openai import ChatOpenAI
import os

lf = get_client()
llm = ChatOpenAI(
    model=os.getenv("MODEL_NAME", "gpt-4o-mini"),
    api_key=os.getenv("MINIMAX_API_KEY"),
    base_url=os.getenv("MINIMAX_BASE_URL"),
)

@observe(as_type="generation", name="ask-critic")
def ask_critic(criticlevel: str, movie: str) -> str:
    prompt = lf.get_prompt("movie-critic")          # 拿带 production 的版本
    compiled = prompt.compile(criticlevel=criticlevel, movie=movie)

    # 关键：把 PromptClient 对象传给当前 generation——这一步让 UI 上出现
    # Prompt 徽章并链接到具体版本。如果只传字符串则不会建链接。
    lf.update_current_generation(
        prompt=prompt,
        model=prompt.config.get("model", "gpt-4o-mini"),
    )

    resp = llm.invoke([
        {"role": "system", "content": compiled},
        {"role": "user",   "content": f"评论一下《{movie}》"},
    ])
    # 顺便记 output 和 token
    lf.update_current_generation(
        usage_details={
            "input_tokens":  resp.usage_metadata["input_tokens"],
            "output_tokens": resp.usage_metadata["output_tokens"],
            "total_tokens":  resp.usage_metadata["total_tokens"],
        },
    )
    return resp.content
    ⚠️ 坑：update_current_generation(prompt=...) 要传 PromptClient 对象（p），不是 compile 后的字符串（compiled）。传字符串只能让 UI 里 input 字段有内容，不会建 prompt 版本链接。这是新手最容易踩的坑——看到 input 有 prompt 文字以为关联好了，结果徽章没出来。

    跑完后 UI 上这条 Generation 节点会显示一个 "Prompt" 徽章，点击直接跳到 movie-critic v1，能 diff 到其它版本——这就是版本化 prompt 真正的价值。

    在 LangChain 里更顺手的写法

    如果整个 agent 都用 LangChain，更简洁的方式是用 get_langchain_prompt() 把 Langfuse prompt 转成 LangChain 的 ChatPromptTemplate，再交给 ChatPromptTemplate.from_template。CallbackHandler 会自动埋点，prompt 关联也会自动建立：

    from langchain_core.prompts import ChatPromptTemplate

p = lf.get_prompt("movie-critic-chat", type="chat")        # 注意 type
chat_prompt = ChatPromptTemplate.from_template(p.get_langchain_prompt())

# 正常用
chain = chat_prompt | llm
result = chain.invoke({"criticlevel": "expert", "movie": "Dune 2"})
    ⚠️ 坑：get_langchain_prompt() 把 {{var}} 转成 LangChain 的 {var} 语法。两者都接受，但你不能再用 .compile(var=...)，要用 LangChain 的 chain.invoke({...})，否则会原样保留 LangChain 占位符。

    7. 缓存、fallback、guaranteed availability

    线上最关心的事：Langfuse 挂了怎么办？

    机制怎么生效行为
    客户端缓存（默认开启）SDK 第一次拉 prompt 后缓存 60s缓存期内 Langfuse 挂了也照常用
    自定义 TTLget_prompt(name, cache_ttl_seconds=300)调到 5 分钟甚至更长
    关闭缓存cache_ttl_seconds=0每次请求都打 Langfuse（不推荐）
    fallback 参数get_prompt(name, fallback="...")拉取失败时返回本地字符串；is_fallback=True
    guaranteed availabilityCLI 工具 langfuse prompt fetch 把 prompt 拉成离线文件本地有副本，Langfuse 挂完全无感
     
    # 推荐生产配置：5 分钟缓存 + fallback
prompt = lf.get_prompt(
    "movie-critic",
    cache_ttl_seconds=300,
    fallback="As a {{criticlevel}} movie critic, do you like {{movie}}?",
)
if prompt.is_fallback:
    # 打日志告警——已经退到 fallback 了
    print("WARN: using fallback prompt")
    ⚠️ 坑：is_fallback=True 时不会在 UI 上建立 prompt 链接。这意味着 fallback 路径跑出来的 trace，prompt 徽章是空的——这是 feature 不是 bug，因为它本来就是"没真的连上 Langfuse"。

    8. 完整 demo：text + chat + 版本切换

    完整可运行 demo 在 src/apps/fuse/prompt_demo.py。它做三件事：

    1. 如果 movie-critic prompt 不存在就创建一个
    2. 再创建一个新版本（把 prompt 措辞改得更"温和"），但不打 production label——保持旧版本线上
    3. 调一次 LLM，跑出 trace，回 UI 看 prompt 徽章指向 v1
    # 第一次跑：会创建 v1
uv run python src/apps/fuse/prompt_demo.py

# 改 prompt 内容再跑：会创建 v2（线上仍跑 v1）
# 登录 UI 把 v2 的 label 加上 production、v1 摘掉 → 切到 v2
# 再跑一次：trace 徽章指向 v2

    核心代码骨架

    """Lesson 0004 · Prompt Management demo."""
import os
from langfuse import get_client, observe
from langchain_openai import ChatOpenAI

PROMPT_NAME = "movie-critic"

llm = ChatOpenAI(
    model="MiniMax-M3",
    api_key=os.getenv("MINIMAX_API_KEY"),
    base_url=os.getenv("MINIMAX_BASE_URL"),
    temperature=0.7,
)


def ensure_prompt_v1() -> int:
    """首次跑时创建 v1；后续跑时跳过。"""
    lf = get_client()
    try:
        v = lf.get_prompt(PROMPT_NAME, label="production").version
        return v
    except Exception:
        lf.create_prompt(
            name=PROMPT_NAME,
            type="text",
            prompt=(
                "As a {{criticlevel}} movie critic, "
                "give a one-line take on {{movie}}."
            ),
            labels=["production"],
            config={"temperature": 0.7, "model": "MiniMax-M3"},
            commit_message="initial version",
        )
        return lf.get_prompt(PROMPT_NAME).version


@observe(as_type="generation", name="ask-critic")
def ask(criticlevel: str, movie: str) -> str:
    lf = get_client()
    p = lf.get_prompt(PROMPT_NAME)                  # 拿 production

    compiled = p.compile(criticlevel=criticlevel, movie=movie)

    # 把 prompt 关联到当前 trace（核心三行）
    lf.update_current_generation(
        prompt=p,                                  # ← 注意：传 PromptClient 对象，不是字符串
        model=p.config.get("model", "MiniMax-M3"),
    )

    resp = llm.invoke([
        {"role": "system", "content": compiled},
        {"role": "user",   "content": f"评论一下《{movie}》"},
    ])
    lf.update_current_generation(
        usage={
            "input":  resp.usage_metadata.get("input_tokens", 0),
            "output": resp.usage_metadata.get("output_tokens", 0),
            "total":  resp.usage_metadata.get("total_tokens", 0),
        },
    )
    return resp.content


def main() -> None:
    v = ensure_prompt_v1()
    print(f">>> current production version = {v}")
    print(f">>> {ask('harsh', 'Dune 2')}")
    print(f">>> {ask('harsh', 'Oppenheimer')}")
    get_client().flush()


if __name__ == "__main__":
    main()

    9. Text Prompt vs Chat Prompt

    Langfuse 有两种 prompt 类型，创建后不能改类型——只能新建一个不同名或带版本号的 prompt。

    维度Text PromptChat Prompt
    形态单字符串 "As a {{role}}..."messages 列表 [{role, content}, ...]
    何时用单轮补全 / FIM 类任务多轮 / system+user 结构化
    compile 返回strlist[dict]（可以直接丢给 chat completion）
    创建示例type="text", prompt="..."type="chat", prompt=[{...}, {...}]
     
    # Chat prompt 创建
lf.create_prompt(
    name="movie-critic-chat",
    type="chat",
    prompt=[
        {"role": "system", "content": "你是 {{criticlevel}} 影评人"},
        {"role": "user",   "content": "一句话评价《{{movie}}》"},
    ],
    labels=["production"],
    commit_message="chat variant",
)

# 拉取 + compile + 直接喂给 LLM
p = lf.get_prompt("movie-critic-chat", type="chat")
messages = p.compile(criticlevel="harsh", movie="Dune 2")
# messages == [
#   {"role": "system", "content": "你是 harsh 影评人"},
#   {"role": "user",   "content": "一句话评价《Dune 2》"},
# ]
resp = llm.invoke(messages)

    10. 常见报错 & 排查

    症状原因排查
    PromptNotFoundErrorprompt 不存在或没打 production label先去 UI 看 Labels 一栏有没有 production
    UI 看不到 prompt 徽章没在 generation 里调 update_current_generation(prompt=...)确认 @observe(as_type="generation") 包裹了 LLM 调用那一段
    变量没替换，原样出现在 prompt 里变量名拼错 / 用了 get_langchain_prompt() 又想 .compile()检查占位符和传参 key 是否完全一致
    is_fallback=True，没有 trace 链接拉取失败 + 缓存空查 Langfuse web 日志；fallback 是设计如此
    UI 上 version 一直不变create_prompt 没真生效（同名但 label 没动）去 UI 看版本列表；labels 是按版本走的
    🎯 动手任务（25 分钟）
    1. 跑 src/apps/fuse/prompt_demo.py 一次，确认 UI 上 movie-critic v1 的 trace 出现了，带 prompt 徽章
    2. 把 prompt 字符串改一个词（比如 harsh → brutal），再跑一次。UI 里现在有两个版本：v1（production）、v2（无 label）。trace 徽章仍指向 v1
    3. 登录 UI，把 v2 加上 production label、把 v1 摘掉。再跑一次。trace 徽章现在指向 v2
    4. 故意把 compile() 的参数名写错（criticlevel 写成 critical_level），观察 UI 里 prompt 是否原样保留了占位符——是的，这就是为什么要做 prompt 校验
    5. （加分）创建一个 chat prompt movie-critic-chat，把 demo 改成 chat 类型，跑通后观察 messages 列表在 UI 里如何显示

    11. 一句话总结

    get_prompt(name) 拿生产版 + compile(**kwargs) 替换变量 + update_current_generation(prompt=...) 把 prompt 钉到 trace 上。
