    LESSON 0006 · OFFLINE EVALUATION

    Dataset + Experiment：上线前评估 prompt 改动

    预计 45 分钟 · 难度 ★★★★☆ · 产出：能用同一组样本跑两个 prompt 版本，看出 score 差异
    本节 4 个目标
    1. 理解离线评估 vs 在线评分的差异
    2. 能建 Dataset（UI + SDK 两种路径）
    3. 能写 task function + 复用 lesson 0005-02 的 evaluator
    4. 能跑 dataset.run_experiment()，对比 v1 vs v2 prompt 的 score

    1. 为什么需要离线评估

    1.1 在线评分不够

    Lesson 0005 解决了"线上给真实流量打分"。但你改 prompt / 换模型前，不能在生产上冒险——你需要一个可控、可复现、低成本的评估方式。

    直觉：在线评分是"心跳监测"（持续观察）；离线评估是"体检"（按需做深度检查）。两者互补，不替代。

    2. Dataset 数据模型

    Langfuse Dataset 由 两个核心实体组成（详见 glossary §5）：

    实体字段关系
    Dataset name / description / metadata 1 个 Dataset → N 个 DatasetItem
    DatasetItem id（稳定 ID，upsert）/ input（dict）/ expected_output（dict，可选） N 个 Item → 1 个 Dataset
    DatasetRunItem（实验产物） 关联 item + 实验 run + 跑出的 trace_id 每次实验产生 N 个
    关键设计：expected_output 是可选——如果你的输出是非确定性（LLM），可以省略，靠 LLM Judge 评分。如果你有 ground truth（如分类标签），就填进去做 exact_match。

    3. 创建 Dataset（两种路径）

    3.1 UI 路径（手工建 / 适合非工程师）

    1. 打开 Langfuse UI → 左侧 Datasets → + New Dataset
    2. 填 name（如 movie-critic-eval-v1）+ description
    3. 点进 dataset → + Add Item → 填 input + optional expected_output
    4. 支持 CSV 导入（菜单 Import CSV）
    5. 支持从 trace 转 item：trace 详情 → Actions → Add to Dataset

    3.2 SDK 路径（可重复 / CI 友好）

    from langfuse import get_client

lf = get_client()

# 1. 创建 Dataset（已存在则不报错）
try:
    lf.create_dataset(
        name="movie-critic-eval-v1",
        description="Evaluate movie-critic prompt on 10 test cases",
    )
except Exception:
    pass  # 已存在则跳过

# 2. 批量添加 item（同 id upsert）
items = [
    {"id": "q1", "input": {"criticlevel": "harsh",  "movie": "Dune 2"},
                "expected_output": None},
    {"id": "q2", "input": {"criticlevel": "kind",   "movie": "Barbie"},
                "expected_output": None},
    # ... 共 10 条
]
for it in items:
    lf.create_dataset_item(
        dataset_name="movie-critic-eval-v1",
        id=it["id"],
        input=it["input"],
        expected_output=it.get("expected_output"),
    )
print("✓ dataset ready:", lf.get_dataset("movie-critic-eval-v1"))
    经验：Dataset 建好后是持久化的——多次实验都跑同一组样本，分数之间才有可比性。dataset item 的 id 必须稳定（建议用题目 id 而非 UUID）。

    4. 写 Task function

    Task 是 "把 DatasetItem 的 input 喂给你的应用，拿到 output" 的函数。签名约定：

    def task(item_input: dict) -> str:
    """接收 dataset_item.input（dict），返回字符串或 dict。

    Langfuse 内部会自动：
    1. 调你的 task 拿到 output
    2. 把 output + input 写成一个 trace（关联到 DatasetRunItem）
    3. 跑 evaluator 给这个 trace 打分
    """
    return my_agent.run(item_input)

    复用 lesson 0004 的 movie-critic prompt：

    from langfuse import get_client

def task(item_input: dict) -> str:
    lf = get_client()
    criticlevel = item_input["criticlevel"]
    movie = item_input["movie"]

    # 拿带 production label 的 prompt（v3）
    p = lf.get_prompt("movie-critic")

    # compile 变量 → 直接喂给 LLM
    compiled = p.compile(criticlevel=criticlevel, movie=movie)

    # 实际调 LLM（OpenAI 兼容）
    resp = client.chat.completions.create(
        model="MiniMax-M3",
        messages=[
            {"role": "system", "content": compiled},
            {"role": "user",   "content": f"评论一下《{movie}》"},
        ],
        temperature=0.7,
    )
    return resp.choices[0].message.content
    ⚠️ task 不能有副作用污染：不要在 task 里打分 / 写 trace / 调 side effect——Langfuse 自动埋点 + evaluator 各自负责。task 只负责"算 input → 出 output"。

    5. 写 Evaluator

    Evaluator 在实验中和 lesson 0005-02 签名相同，但有一点关键差异：

    场景能不能拿到 expected_output？
    在线评分（Lesson 0005） ❌ 没有 → 只评 output 本身
    离线实验（本节） ✅ DatasetItem.expected_output 可用 → 可做 exact_match / 黄金集对比

    5.1 Exact match（黄金集场景）

    def evaluator_exact_match(*, expected_output, output, **kwargs):
    """当 expected_output 有值时，与 output 做严格匹配。"""
    if expected_output is None:
        return None  # 跳过无 ground truth 的样本
    return 0.0 if output == expected_output else 1.0
    参数约定：Evaluator 函数必须接受 **kwargs（Langfuse 传 input / output / expected_output / metadata / trace 等关键字）。返回 None 表示跳过此条样本。

    5.2 复用 lesson 0005-02 的 LLM Judge

    judge_helpfulness 直接搬过来用——LLM Judge 不需要 ground truth：

    from src.apps.fuse.scoring_demo import judge_helpfulness

def evaluator_llm_judge(*, input, output, **kwargs):
    """复用 0005-02 的 judge 函数，包一层签名适配。"""
    question = f"电影评论（{input.get('criticlevel', '?')}）"
    value, comment = judge_helpfulness(question, output)
    return {"value": value, "comment": comment}

    返回 dict 时会自动拆成 value + comment 两个字段写到 score 里。

    6. 跑 Experiment

    dataset.run_experiment() 是核心 API，它自动串起：

    6.1 API 完整签名

    dataset = lf.get_dataset("movie-critic-eval-v1")

result = dataset.run_experiment(
    name="prompt-v2-baseline",          # ← run 名（显示在 UI）
    description="Baseline against v2 production prompt",
    task=task,                          # ← 你的应用函数
    evaluators=[                         # ← evaluator 列表（可多个）
        evaluator_exact_match,
        evaluator_llm_judge,
    ],
)
print(result)
    ⚠️ 重要：同一个 Dataset 上多次跑 experiment，不要重名（不同 run 用不同 name）。Langfuse 会按 name 区分实验，UI 上的对比视图会列出同名 run。

    7. 对比两个 Prompt 版本

    这是 Lesson 0006 的最终目标——用同一组样本跑两个 prompt 版本，看 score 差异。

    7.1 怎么做

    # 在 Langfuse Prompt Management 创建 v3 版本：
#   - 拿现 production v2 的 prompt
#   - UI 编辑 + 加 labels=["staging"]（先不上 production）
# v2 = production，v3 = staging

# 第一次跑实验：用 production v2 prompt
def task_v2(item_input):
    p = lf.get_prompt("movie-critic", label="production")  # = v2
    ...

run_v2 = dataset.run_experiment(name="v2-production", task=task_v2, evaluators=[...])

# 切到 v3：把 v3 label 从 staging 改成 production（或反向用 label）
# 第二次跑实验：用 v3 prompt
def task_v3(item_input):
    p = lf.get_prompt("movie-critic", label="production")  # 现在 = v3
    ...

run_v3 = dataset.run_experiment(name="v3-staging", task=task_v3, evaluators=[...])

    7.2 决策框架：哪个版本好？

    指标看哪个值？怎么解读
    mean helpfulness v3.mean vs v2.mean v3 > v2 = prompt 改善；但要验证 统计显著（n=10 不够，至少 50+）
    std（方差） v3.std vs v2.std v3.std 小 = 输出一致性更好（reduce hallucination）
    pass rate（exact_match） v3.pass_rate vs v2 只适用于分类 / 抽取任务；开放式回答没用
    token 用量 v3.total_tokens vs v2 v3 token 多了但 score 只涨 5% → 性价比低 → 回滚
    p95 latency v3.p95 vs v2 prompt 变长 → latency 涨是预期，但 >30% 警惕

    8. 常见坑

    坑 1：Dataset 太小（n<10），分数不可信
    LLM Judge 输出有随机性，n=5 时 ±0.2 都不奇怪。要可靠对比，至少 n=50+；生产决策要 n=200+。
    坑 2：把 expected_output 写死 → LLM judge 没法 catch 真正的问题
    LLM 输出本质不确定。如果你想测"输出含 X 关键词"，要么用 exact_match，要么把 expected_output 留空让 LLM Judge 评。别用真实输出作 expected（那等于裁判自己写答案）。
    坑 3：实验 run name 重复 → 覆盖历史数据
    每次跑 run_experiment 用新名字（含 prompt 版本 + 日期），便于 UI 对比。
    坑 4：实验时忘了 flush()
    短脚本必须 lf.flush()，否则 trace / score 留在内存队列里丢失。Lesson 0005-01 §1.4 讲过。
    坑 5：task 函数污染 trace
    task 里再调 @observe 或手动创建 trace 会双层 trace 嵌套。task 只管业务，不动 Langfuse 状态。

    9. 一句话总结

    Dataset = 固定样本集，Experiment = 跑应用 × 评分。同一 Dataset 多次跑 = 不同 prompt 版本直接可比。
