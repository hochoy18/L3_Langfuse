    LESSON 0003 · AGENT TRACE

    把 LangGraph ReAct Agent 接入 Langfuse

    预计 30 分钟 · 难度 ★★★☆☆ · 产出：UI 里看到一棵完整的多步 trace 树（agent → tool → llm → tool → llm）
    本节目标
    用 LangGraph 的 create_react_agent 搭一个最小 ReAct，一行 CallbackHandler 接进 Langfuse，UI 里能看到每次 LLM 调用 + 每次 Tool 调用作为子节点挂在同一棵 trace 树下。

    1. 为什么 Agent 必须有 trace

    单次 OpenAI 调用的 hello trace 你已经看到了——一张扁平的 trace + 一个 Generation。但 Agent 不一样：

    场景没有 trace 时有 trace 时
    "这个回答为什么错了"翻日志，猜是哪一步出问题UI 直接看到是哪次 LLM 调用走的岔路
    "为什么 token 这么多"统计 chat history 总长度每一步 Generation 都列了 prompt / completion / tokens
    "Agent 死循环了"进程卡死，看不到栈trace 树一眼看到 20 层一样的 span 嵌套

    2. 最小 ReAct：两个工具

    完整可运行代码在 src/apps/fuse/react_agent.py。先看核心：

    from datetime import datetime
from langchain_core.tools import tool
from langchain_openai import ChatOpenAI
from langgraph.prebuilt import create_react_agent

@tool
def add(a: int, b: int) -> int:
    """返回 a + b。"""
    return a + b

@tool
def now() -> str:
    """返回当前时间（ISO 格式）。"""
    return datetime.now().isoformat(timespec="seconds")

llm = ChatOpenAI(model="MiniMax-M3", temperature=0)
agent = create_react_agent(llm, [add, now])

    三件事：

    组件作用
    @tool把 Python 函数包装成 LangChain 工具（自动从 docstring 抽 schema）
    ChatOpenAI一个 Runnable，调一次就是一次 LLM 调用
    create_react_agentLangGraph 的预制 ReAct：内部帮你拼好 agent → tool → agent → … 这条边
    说明：create_react_agent 背后是个 StateGraph，节点只有两个——agent（调 LLM 决定下一步）和 tools（执行工具调用）。每次循环把工具结果写回 messages，再调一次 LLM，直到 LLM 决定不再调工具。

    3. 一行接入 Langfuse

    核心就这一步——构造一个 CallbackHandler，传进 LangChain 的 config：

    from langfuse.langchain import CallbackHandler

handler = CallbackHandler()  # 默认读 .env 里的 LANGFUSE_* 配置

result = agent.invoke(
    {"messages": [{"role": "user", "content": "现在几点了？把秒数加 100。"}]},
    config={
        "callbacks": [handler],
        "metadata": {
            "langfuse_session_id": "demo-001",
            "langfuse_user_id": "demo-user",
            "langfuse_tags": ["lesson-0003", "react"],
            "langfuse_trace_name": "react-agent-demo",
        },
    },
)

    Langfuse 约定的 metadata key（langchain 专用）

    不是所有 metadata 都会被 Langfuse 识别。只有这几个 key 会触发特殊处理：

    Key作用值类型
    langfuse_session_id把这条 trace 归到某个 session（多轮对话）str
    langfuse_user_id归到某个 user，做用户级聚合str
    langfuse_tags给 trace 打标签，方便过滤list[str]
    langfuse_trace_name自定义 trace 名字（默认会用 chain / agent 的 class 名）str
    ⚠️ 坑：key 是 带 langfuse_ 前缀的，不是直接 session_id。LangChain 自己也有 session_id 这个 metadata key（LangSmith 兼容），两者名字冲突，Langfuse 必须用前缀区分。

    剩下随便写什么 metadata 都会原样存到 trace / observation 上，作为附加字段。

    4. 跑 + 看 UI 里的 trace 树

    uv run python src/apps/fuse/react_agent.py

    控制台会打印最终答案和 trace id = ...。浏览器切到 localhost:3000，左侧 Tracing 找到 react-agent-demo，你会看到一棵这样的树：

    Trace: react-agent-demo             ← session_id=demo-001, user_id=demo-user
└─ Agent: LangGraph                 ← 整张图是一个 Agent observation
   ├─ Generation #1: MiniMax-M3     ← 第 1 次 LLM 调用，决定调哪个工具
   │   ├─ input:    "现在几点了？…"
   │   ├─ output:   tool_calls=[{name: now}]
   │   └─ tokens:   35 in / 18 out
   ├─ Tool: now                     ← 第 1 个工具执行
   │   └─ output:   "2026-09-16T13:42:07"
   ├─ Generation #2: MiniMax-M3     ← 第 2 次 LLM 调用，决定再调 add
   │   ├─ input:    [..., tool_result]
   │   ├─ output:   tool_calls=[{name: add, args: {a: 7, b: 100}}]
   │   └─ tokens:   78 in / 22 out
   ├─ Tool: add
   │   └─ output:   107
   └─ Generation #3: MiniMax-M3     ← 第 3 次 LLM 调用，给最终答案
       ├─ input:    [..., tool_result]
       ├─ output:   "把秒数加 100 后是 107"
       └─ tokens:   95 in / 24 out

    节点类型映射

    LangChain 事件Langfuse Observation 类型图标
    on_chain_start (create_react_agent)Agent🤖
    on_llm_start / on_llm_endGeneration✨
    on_tool_start / on_tool_endTool🔧
    on_retriever_startRetriever📚

    5. @observe 装饰器 vs CallbackHandler

    两种接入方式各有用途，不要混用包同一段代码：

    方式适合场景粒度
    @observe()包自己写的工具函数、预处理/后处理逻辑整段函数一个 span
    CallbackHandler()LangChain / LangGraph 自动埋点每个 chain / llm / tool 都建节点

    实际项目里通常是外层用 @observe 包业务函数，里面跑 LangGraph。两层会自动嵌套：

    @observe(name="user_request")
def handle(question: str) -> str:
    handler = CallbackHandler()
    return agent.invoke(
        {"messages": [{"role": "user", "content": question}]},
        config={"callbacks": [handler]},   # ← 复用外层 trace，不会另开
    )

    关键点：CallbackHandler() 默认会把所有 event 挂到当前激活的 Langfuse context下——也就是外层 @observe 创建的 trace。无需手动传 trace_id。

    ⚠️ 坑：别在已经跑了 @observe 的代码里再 from langfuse.openai import openai 来手动构造 OpenAI client 调 LLM——会出现"trace 嵌套两层 trace"的诡异现象，因为 langfuse.openai 不知道外层有 observe，会自己新开一个 Trace。lesson 0002 的 hello_trace 模式只适合裸调用 OpenAI，Agent 场景请走 LangChain。

    6. 进阶：手工 StateGraph 的细微差别

    create_react_agent 是预制件，省事但看不到节点名字。如果你要更精细的控制（自定义节点、并行分支、子图），用 StateGraph 手写：

    from langgraph.graph import StateGraph, START, END
from typing import TypedDict, Annotated
from langgraph.graph.message import add_messages

class S(TypedDict):
    messages: Annotated[list, add_messages]

g = StateGraph(S)
g.add_node("planner", planner_fn)   # 自定义节点
g.add_node("tools", tool_node)
g.add_edge(START, "planner")
g.add_conditional_edges("planner", should_call_tools)
g.add_edge("tools", "planner")
app = g.compile()

    CallbackHandler 同样工作。每个 add_node(name, fn) 中的 name 会作为 observation 的名字出现在 UI 上——取名要清晰，这是你看 trace 的主要索引。

    7. 常见报错 & 排查

    症状原因排查
    UI 看不到 traceCallbackHandler 没生效 / Langfuse 没收到检查 handler.last_trace_id 是否非空
    trace 出现但没有子节点callback 装在了错的 chain 上确认 config 传给了 agent.invoke，不是 llm.invoke
    Tool 节点显示 raw 字符串而不是 JSONTool 的 schema 描述太弱给 @tool 函数的 docstring 第一行写清楚参数
    LLM 决定不调工具但 answer 为空模型不熟悉 tool call 协议换模型 / 检查 create_react_agent 用的 prompt 是否被覆盖
    🎯 动手任务（20 分钟）
    1. 把 src/apps/fuse/react_agent.py 跑通。打开 UI，点开那条 trace，数一下有几层节点、几次 LLM 调用
    2. 加第三个工具 multiply(a, b)，构造一个需要连续两次乘法的题目（比如 "(7*8)*9"），跑一次，看 trace 是不是 5 层（agent → llm → tool → llm → tool → llm）
    3. 故意把 @tool 的 docstring 写得很模糊（比如只写 "do math"），观察模型是否还能正确选择工具
    4. 在 UI 上用 session_id 过滤，只看 demo-001 这一条；然后改 langfuse_session_id 再跑一次，确认不同 session_id 不会混在一起

    8. 一句话总结

    LangGraph agent 不需要写任何埋点代码——构造一个 CallbackHandler() 塞到 config["callbacks"] 里，整棵调用树就自动出来了。
